# Implementation Plan: Developer Documentation Site

**Branch**: `002-developer-docs` | **Date**: 2026-07-26 | **Spec**: `specs/002-developer-docs/spec.md`

## Summary

Create a Docusaurus 3.x documentation site at `docs/` within the monorepo, providing per-package API reference (auto-generated from TypeScript via TypeDoc), usage guides, LLM-optimized reference, emulator setup guide, and CI/CD deployment to GitHub Pages. The site serves as the single source of truth for developers and AI coding assistants using `@agnostic-cloud/*`.

## Technical Context

| Dimension | Decision |
|-----------|----------|
| **Generator** | Docusaurus 3.x (React-based, MDX, versioning, search) |
| **API Docs** | TypeDoc + `docusaurus-plugin-typedoc` — auto-generates from `packages/*/src/index.ts` |
| **Hosting** | GitHub Pages via `peaceiris/actions-gh-pages` or native GHA deploy |
| **Search** | Algolia DocSearch (OSS: free for open source) |
| **Styling** | Docusaurus Infima + custom CSS; diagramas con Mermaid via `@docusaurus/theme-mermaid` |
| **Node** | >=18 (matches monorepo requirement) |
| **Package Manager** | npm (matches monorepo) |

## Key Decisions (Clarified)

| Decision | Resolution |
|----------|-----------|
| Versioning | Docusaurus versioning desde día 1. Versión inicial `0.1.0`. `current` = `main`. Releases congelan snapshot. |
| Interactive examples | Bloques de código + CloudTabs + Copy button. Sin ejecución en navegador. |
| docs/ package.json | Independiente. No es workspace member. Evita conflictos de dependencias. |

## Constitution Check

- **II (Library-First)**: Docs describe public API — no internal implementation details exposed
- **III (Minimal Dependencies)**: Docusaurus is a dev/docs dependency, not a runtime dep
- **IV (TypeScript Strictness)**: TypeDoc generates API reference directly from source types
- **VI (Observability & Errors)**: Error reference covers full typed error hierarchy

### Per-Package Page Template
Each package section follows the same structure:
1. **Overview** — Purpose, supported clouds, factory function
2. **Installation** — `npm install @agnostic-cloud/xxx`
3. **API Reference** — Auto-generated from TypeDoc
4. **Usage Examples** — CloudTabs con AWS/GCP/Azure
5. **Configuration** — `Config` type breakdown
6. **Error Handling** — Package-specific errors

## CI/CD Pipeline

```yaml
# .github/workflows/docs.yml
on:
  push:
    branches: [main]
    paths: ['docs/**', 'packages/**/src/**']
  pull_request:
    paths: ['docs/**']

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
      - run: npm ci
      - run: npm run build -w packages  # build all packages for typedoc
      - run: npm run build              # build docusaurus
      - uses: peaceiris/actions-gh-pages@v3
        if: github.ref == 'refs/heads/main'
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./docs/build
```

## Complexity Tracking

| Violation / Deviation | Why Needed | Simpler Alternative Rejected Because |
|-----------------------|------------|--------------------------------------|
| Separate `package.json` in `docs/` | Docusaurus has its own React deps — hoisting to root causes peer-dep conflicts | Root-level Docusaurus install breaks monorepo workspace resolution |
| TypeDoc generates per-package pages instead of one monolith | Each package is independently published — users need isolated reference | Single page is too long (7 packages × ~10 methods each) |
| Manual `CloudTabs` component instead of auto-generation | Each example differs slightly per cloud (config shape, region, etc.) | Template strings with conditionals reduce readability |
