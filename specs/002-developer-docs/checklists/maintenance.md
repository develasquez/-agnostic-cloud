# Maintenance Checklist — Developer Documentation Site

## Requirement Completeness

- [ ] CHK001 Is there a documented release process for the docs site (version bump, changelog, deploy)? [Gap]
- [ ] CHK002 Is there a documented process for adding a new package to the docs (scaffold, TypeDoc, sidebar)? [Spec §US2]
- [ ] CHK003 Is there a documented process for adding a new cloud provider to an existing package? [Spec §FR-018]
- [ ] CHK004 Is there a way to preview docs changes locally before deploying? [Spec §US8]
- [ ] CHK005 Is there a CI pipeline that builds and deploys docs on merge to main? [Spec §FR-002]
- [ ] CHK006 Is there a CI check for broken links? [Gap]
- [ ] CHK007 Is there a CI check for stale/generated files (TypeDoc out of sync with source)? [Gap]
- [ ] CHK008 Is there a documented process for deprecating a page or section? [Gap]
- [ ] CHK009 Is there a documented process for archiving old versions? [Spec §US6]

## Requirement Clarity

- [ ] CHK010 Is "stale documentation" defined (e.g., TypeDoc not regenerated after source change, quickstart example outdated)? [Clarity]
- [ ] CHK011 Is the cadence of TypeDoc regeneration specified (pre-commit hook, CI, manual)? [Clarity, Spec §FR-006]
- [ ] CHK012 Is the docs ownership documented (who reviews docs PRs, who deploys)? [Clarity, Spec §Roles]

## Requirement Consistency

- [ ] CHK013 Do all 7 packages follow the same documentation update workflow? [Consistency]
- [ ] CHK014 Is the sidebar update process documented consistently (manual `sidebars.js` edit vs auto-generation)? [Consistency]
- [ ] CHK015 Are deprecation notices formatted consistently across all pages? [Consistency]

## Acceptance Criteria Quality

- [ ] CHK016 Can the release process be verified by following the documented steps end-to-end? [Measurability]
- [ ] CHK017 Can stale TypeDoc output be detected programmatically (compare `git diff` on source vs generated)? [Measurability]
- [ ] CHK018 Can broken links be verified via `docusaurus build` (built-in link checker)? [Measurability]

## Scenario Coverage

- [ ] CHK019 Is the process for adding a new package documented and tested (scaffolding, TypeDoc config, sidebar entry)? [Coverage, Spec §FR-018]
- [ ] CHK020 Is the process for releasing a new docs version documented (version command, archive, redirect)? [Coverage, Spec §US6]
- [ ] CHK021 Is the process for reverting a broken deployment documented? [Coverage]
- [ ] CHK022 Is the process for updating the CloudTabs component (adding a cloud provider tab) documented? [Coverage, Spec §FR-012]
- [ ] CHK023 Is the process for updating the TypeDoc theme/plugin version documented? [Coverage, Spec §FR-006]

## Edge Case Coverage

- [ ] CHK024 What happens when a package is removed from the monorepo (docs removal process)? [Edge Case]
- [ ] CHK025 What happens when a cloud provider SDK breaking change affects example code? [Edge Case]
- [ ] CHK026 What happens when Docusaurus itself has a breaking upgrade? [Edge Case]
- [ ] CHK027 What happens when GitHub Pages deployment fails mid-deploy (partial deploy)? [Edge Case]

## Non-Functional Requirements (Maintenance)

- [ ] CHK028 Is the docs build reproducible (deterministic output, lockfile)? [Gap]
- [ ] CHK029 Are docs dependencies regularly updated (Dependabot/Renovate for `docs/package.json`)? [Gap]
- [ ] CHK030 Is there a documented rollback procedure for docs deployment? [Gap]
- [ ] CHK031 Is there a documented backup strategy for documentation content (source is in Git, but translations?) [Gap]
- [ ] CHK032 Is the monitoring of docs site availability documented (uptime check, 404 monitoring)? [Gap]
- [ ] CHK033 Are docs build times tracked over time to detect regressions? [Gap, ties to SC-005]
- [ ] CHK034 Is there a documented SLA for docs content updates (e.g., within 1 business day of a source change)? [Gap]

## Dependencies & Assumptions

- [ ] CHK035 Does maintenance assume the deployer has GitHub admin access to the repository? [Assumption]
- [ ] CHK036 Does the CI pipeline assume GitHub Actions with `peaceiris/actions-gh-pages`? [Assumption, Spec §FR-002]
- [ ] CHK037 Does TypeDoc regeneration assume the user has all devDependencies installed in the root monorepo? [Assumption, Spec §FR-006]

## Ambiguities & Conflicts

- [ ] CHK038 Is it clear whether docs changes should be in the same PR as source changes or a separate PR? [Ambiguity]
- [ ] CHK039 Is it clear who is responsible for keeping the TypeDoc API reference in sync with source — CI or the developer? [Ambiguity]
- [ ] CHK040 Is it clear whether versioned docs are manually copied or auto-generated by `docusaurus docs:version`? [Ambiguity, Spec §US6]
