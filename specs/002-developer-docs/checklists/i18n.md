# i18n Checklist — Developer Documentation Site

## Requirement Completeness

- [ ] CHK001 Is the i18n roadmap documented (locales, priority, target completion)? [Spec §FR-018]
- [ ] CHK002 Is the default locale (`en`) fully supported before any additional locale work begins? [Spec §FR-018]
- [ ] CHK003 Is the Docusaurus i18n plugin configured with at least the default locale? [Spec §FR-018]
- [ ] CHK004 Is the locale dropdown/selector available in the navbar? [Gap]
- [ ] CHK005 Is the RTL layout supported if applicable (e.g., Arabic, Hebrew)? [Gap]
- [ ] CHK006 Are all UI strings externalized (navbar labels, sidebar labels, footer text, search placeholder)? [Spec §FR-018]
- [ ] CHK007 Is the site metadata (title tag, meta description) localizable per locale? [Spec §FR-018]
- [ ] CHK008 Are date and number formats locale-aware in documentation examples? [Gap]
- [ ] CHK009 Are code examples **not** translated (code stays in English across all locales)? [Assumption]

## Requirement Clarity

- [ ] CHK010 Is "internationalized" (FR-018) scoped to documentation prose only, or does it include the API reference (TypeDoc output)? [Clarity, Spec §FR-018]
- [ ] CHK011 Is it clear whether community translations are accepted via Crowdin or PR-based? [Clarity, Spec §FR-018]

## Requirement Consistency

- [ ] CHK012 Do all locales follow the same URL structure (`/locale/` prefix)? [Consistency, Docusaurus default]
- [ ] CHK013 Are translation files organized consistently (per-locale JSON for UI, per-locale `docs/` for content)? [Consistency]
- [ ] CHK014 Is the fallback behavior consistent (missing translation → English, not broken page)? [Consistency]

## Acceptance Criteria Quality

- [ ] CHK015 Can FR-018 be verified by switching locale and confirming all visible UI strings are translated? [Measurability]
- [ ] CHK016 Can locale completeness be measured as a percentage (translated strings / total strings)? [Measurability]
- [ ] CHK017 Can the fallback behavior be verified by intentionally removing a translation? [Measurability]

## Scenario Coverage

- [ ] CHK018 Is the landing page tested in all supported locales for layout breaks (longer/shorter text)? [Coverage]
- [ ] CHK019 Are per-package pages with CloudTabs tested in all supported locales? [Coverage, Spec §US2]
- [ ] CHK020 Is the quickstart page step-by-step guide tested in all supported locales? [Coverage, Spec §US3]
- [ ] CHK021 Is the LLM reference section excluded from i18n (English-only, machine-optimized)? [Coverage, Spec §US5]
- [ ] CHK022 Are versioned docs (`next`, `0.1.0`) i18n-aware (per-version, per-locale)? [Coverage, Spec §US6]

## Edge Case Coverage

- [ ] CHK023 What is the UI state when a specific page translation is missing (partial locale coverage)? [Edge Case]
- [ ] CHK024 Are TypeDoc auto-generated API pages localizable (class/interface/method descriptions)? [Edge Case, ties to FR-006 vs FR-018]
- [ ] CHK025 Is the search index locale-aware (language-specific tokenization, stemming)? [Edge Case]
- [ ] CHK026 Are Mermaid diagram labels localizable? [Edge Case]

## Non-Functional Requirements (i18n)

- [ ] CHK027 Does locale switching preserve the current page (not redirect to root)? [Gap]
- [ ] CHK028 Does locale switching preserve scroll position and sidebar state? [Gap]
- [ ] CHK029 Is the build-time impact of multiple locales measured (N locales ≈ N× build time for SSG)? [Spec §SC-005]
- [ ] CHK030 Are right-to-left (RTL) stylesheets prepared for future RTL locales? [Gap]

## Dependencies & Assumptions

- [ ] CHK031 Are translations managed via Docusaurus Crowdin integration, plain JSON files, or a custom solution? [Assumption, Spec §FR-018]
- [ ] CHK032 Is TypeDoc output excluded from i18n (typedoc-plugin-markdown outputs English only)? [Assumption]
- [ ] CHK033 Does i18n assume GitHub Actions with matrix builds for each locale? [Assumption]

## Ambiguities & Conflicts

- [ ] CHK034 Is there a conflict between "versioned docs" and "i18n" (N versions × M locales × P pages = combinatorial explosion)? [Conflict, Spec §US6 vs FR-018]
- [ ] CHK035 Is it clear whether CloudTabs labels ("AWS", "GCP", "Azure") should be translated or kept as abbreviations? [Ambiguity, Spec §FR-012]
- [ ] CHK036 Is the order of priority between versioning and i18n clear (version first, then translate latest)? [Ambiguity]
